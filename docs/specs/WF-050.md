# WF-050 — Bounded input and truthful API failures

## Purpose

A Workframe API response must distinguish malformed input, forbidden scope,
not-found resources, unavailable storage, corrupt state, conflict, and a valid
empty result. Request parsing must be bounded before allocation or interpretation.

This rail tightens the current `http.server` implementation. It does not replace
it with a framework or redesign product schemas.

## Input contract

One reader owns JSON request bodies:

1. accept only the expected JSON media type in secure mode;
2. parse `Content-Length` strictly and reject invalid or negative values;
3. enforce a configurable byte ceiling before and while reading;
4. reject incomplete bodies and bodies larger than declared;
5. decode UTF-8 strictly;
6. require a JSON object where route handlers expect one;
7. return `400 invalid_json` or `invalid_body`, `413 payload_too_large`, and
   `415 unsupported_media_type` without executing a handler or mutation;
8. never map malformed JSON to `{}`.

Use a small typed exception/result and the existing response helpers. Do not add
a validation framework.

## Failure vocabulary

Use stable public codes with nonsecret details:

- `not_found` — resource does not exist or is intentionally undisclosed;
- `forbidden` — caller lacks authority;
- `invalid` — client input is invalid;
- `conflict` — valid request conflicts with current state;
- `unavailable` — required database/runtime/provider dependency cannot be read;
- `corrupt` — persisted state exists but cannot be parsed or trusted.

Infrastructure failure must never return `ok: true` with an empty collection.
Valid empty collections remain HTTP 200.

## Required first pass

- replace `Handler._read_json()` with the bounded strict reader and use it for
  POST/PATCH/DELETE and internal record/proxy JSON paths where applicable;
- bound and validate room-message pagination;
- replace broad empty-success fallbacks in room members/messages, workspace
  invites, memory, budget, and grants with typed unavailable/corrupt responses;
- use context-managed DB connections in the touched handlers;
- keep response bodies free of stack traces, secrets, and host filesystem paths;
- add fault fixtures that prove no database/filesystem mutation on parse or
  backend failure.

## Acceptance matrix

- valid empty object and valid empty collection;
- malformed JSON, non-object JSON, invalid UTF-8, negative/invalid/missing
  length, incomplete body, declared/actual mismatch, and over-limit streaming;
- invalid, negative, and excessive pagination;
- DB open/query/decode failures for room members/messages, invites, memory,
  budget, and grants;
- unchanged state after every rejected request;
- normal install/auth/scope/package tests remain green.

## Non-goals

- no web-framework migration;
- no credential lifecycle work (WF-048);
- no runtime ownership work (WF-049);
- no new schema library;
- no verbose public exception strings.

## Completion

Code-complete requires deterministic parser/fault regressions and the full CI,
package, install, auth, and target-scope suites. Four-cell production acceptance
remains WF-046.
