# WF-047 — Target-resource authorization and legacy mutation closure

**Issue:** #18  
**Priority:** P0  
**Status:** implemented; repository verification pending

## Intent

Authentication answers who is calling. Workframe authorization must additionally prove which workspace-owned resource the caller may access and what authority the caller has in that resource's workspace.

## Invariants

1. Stack operation and workspace administration are separate authorities.
2. A role in workspace A grants no authority in workspace B.
3. A scoped handler never derives authority from the caller's highest role elsewhere.
4. Every workspace, room, memory, agent-credential, and invite path resolves to one target workspace before handler execution.
5. Raw provider secrets are never returned by the scoped profile or credential surfaces; runtimes receive opaque, revocable capabilities.
6. Legacy bootstrap/setup routes cannot bypass the canonical install authority.

## Design

`auth_gate.authorize_request()` now performs three ordered decisions:

```text
authenticate caller
→ attach stack role
→ resolve target resource to workspace
→ attach target-workspace role
→ enforce member or owner/admin requirement
→ dispatch handler
```

The target resolver supports:

- `/api/workspace/{id|slug}/...`;
- `/api/rooms/{id}/...`;
- `/api/memory/{id}`;
- `/api/agents/{id|slug}/credentials` when the slug resolves unambiguously;
- `/api/invites/{token}` and `/accept`, bound to the authenticated invited email and expiry.

Administrative or destructive workspace operations require target owner/admin authority. Collaboration reads and writes require target membership, with narrower room-level and creator-level checks retained inside their domain handlers.

## Legacy routes

- `/api/auth/bootstrap` is denied in secure mode. The canonical first-owner path is `/api/install/register-admin` during an open install window.
- `/api/setup` requires an open install window plus an authenticated stack owner/admin. It remains a compatibility path, not public product authority.

## Acceptance matrix

The regression fixture includes:

- owner of A and member of B;
- owner of A only;
- owner of B;
- member of B;
- invited identity for B.

It asserts both direct workspace paths and indirect room, memory, agent, and invite scopes. The critical proof is that the owner-of-A/member-of-B request carries `auth_stack_role=owner` but `auth_role=member` while acting on B.

## Non-goals

This slice does not claim to finish:

- long-running stream revocation after authorization;
- transactional credential publication across vault, database, leases, and runtimes;
- workspace qualification for every Hermes template/profile mutation whose workspace currently arrives only in the request body;
- replacement of the legacy handler mixin/service-locator architecture;
- the immutable four-instance beta matrix.

Those remain explicit release rows rather than hidden caveats.

## Stop line

Do not invite external multi-user beta participants until this contract is green and the same immutable package passes WF-046 on all target cells.
