# Workframe Origin — One-Page Summary

People install an agentic tool, open a session, and spend an hour explaining a project: who they are, what they are trying to achieve, which files matter, what has already been decided, what must never happen, and how the work fits into the rest of their life or organization. The session ends. The next day, a new session begins as a generic assistant with little or no reliable understanding of the user or project. Conventional memory features only partly address this because the remembered material is often hidden, provider-bound, difficult to correct, weakly sourced, and unable to distinguish facts from assumptions or temporary conversation.

Workframe Origin is a CLI-first epistemic bootstrapper for durable human–AI collaboration. It starts by discovering the actual environment: operating system, installed agentic runtimes, authenticated CLI sessions, model-provider posture, repositories, likely workspace roots, and existing Architectonic or Workframe installations. Discovery is local, progressive, and permission-bounded. The system explains what it found, asks which runtime or provider it may use, uses existing authentication in place when possible, imports only user-supplied keys with explicit consent, and may offer a tightly metered Workframe-hosted inference relay when no local or user-funded path exists. It never treats detection as authorization.

After establishing an authorized inference path, the system begins formation rather than installation-by-template. It asks to inspect increasingly specific evidence: first machine and path metadata, then selected file inventories, then the contents of exact folders or documents. Its dialogue follows a disciplined order: teleology first—what is this for; ontology second—what entities, actors, projects, systems, and boundaries exist; epistemology third—what is known, how it is known, which sources govern, and what remains uncertain; then doctrine, authority, privacy, constitution, project structure, work coordination, skills, agents, models, and upkeep. Questions are not generic form fields. The system compares authorized sources, identifies the highest-value contradiction or missing decision, explains why it matters, asks one focused question, proposes a durable document change, and preserves unresolved unknowns rather than inventing completion.

The output is a customized, file-native Architectonic instance. Depending on the user's real needs, it may contain an organization, constitution, doctrine, actor and authority model, knowledge corpus, skills, installed agents, projects, and one Rail ledger for each project that requires durable coordination. Existing repositories can be cloned into an approved workspace, existing folders can be mounted or referenced without being moved, and selected files can be copied with provenance. Every attachment records source, mode, scope, sensitivity, authority, and refresh behavior. Agents are bound to explicit owners, purposes, tools, model policies, data access, spending limits, review gates, escalation paths, and stopping rights. Installed files alone grant no authority.

Workframe then becomes the operating surface over that durable system. Users can open rooms, agent DMs, files, projects, Rails, approvals, artifacts, and current work while one or more authorized runtimes execute beneath it. A future Claude, Codex, Hermes, Pi, or other runtime does not need proprietary hidden memory to continue. It reads the same user-owned purpose, project truth, decisions, evidence, permissions, and current work. The result is not an assistant that vaguely remembers a person. It is a persistent, inspectable collaboration environment in which the human and every authorized agent can answer: who am I, who is my user, what are we doing, what is known and unknown, what may I do, and what is the next useful action?

## Product flow

```text
install or run CLI
  -> read-only machine and runtime discovery
  -> explicit authorization of one inference path
  -> progressive, revocable evidence access
  -> teleology-first Socratic formation
  -> Architectonic plan and file diffs
  -> approved atomic installation
  -> project and repository attachment
  -> one Rail per project when justified
  -> agent, model, skill, and permission binding
  -> Workframe deployment or attachment
  -> verification and resumable ongoing upkeep
```

## Outcome statement

> The user finishes with a portable, source-grounded knowledge and operating system attached to a persistent workspace and one or more replaceable agent runtimes—not another chat that knows everything for an hour and nothing tomorrow.
