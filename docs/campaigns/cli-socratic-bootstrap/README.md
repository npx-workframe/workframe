## Campaign purpose

This campaign explores a consent-driven system that discovers a user's computing environment, identifies available agentic runtimes and model access, conducts an evidence-led Socratic formation process, installs a customized Architectonic system of record, and attaches that system to a Workframe execution surface and one or more agentic runtimes.

It addresses a common failure in present-day AI use: a person spends an hour explaining who they are, what they are building, what matters, what already exists, and what constraints apply; the session ends; the next agent begins without that understanding. The problem is not merely conversational memory. The missing layer is a durable, user-owned account of purpose, entities, knowledge, authority, projects, decisions, unknowns, permissions, and current work.

Workframe Origin ultimately aims to answer, with the user and from authorized evidence:

```text
Who am I?
Who is my user?
What are we trying to accomplish?
What already exists?
What is known?
What is assumed?
What is unknown or contradictory?
What may I access, change, publish, spend, or execute?
How can I be useful now?
How will this understanding survive the current session and model?
```

## Product thesis

The canonical chat transcript should remain disposable. Durable understanding should be explicit, inspectable, correctable, source-grounded, portable across runtimes, and owned by the user.

```text
conversation
  -> evidence-led questions
  -> explicit decisions and preserved unknowns
  -> Architectonic files and contracts
  -> Workframe users, rooms, runs, approvals, and artifacts
  -> runtime-specific sessions that can resume from the same ground truth
```

Architectonic provides the durable organizational and knowledge contract. Workframe provides the operating environment in which humans and agents use that contract. Existing runtimes remain replaceable execution engines.

## Source principles retained by this campaign

1. **Purpose before form.** Establish the intended outcome, beneficiary, and success condition before proposing organization, business, project, or installation.
2. **Files outrank chat.** Durable project and organizational truth belongs in inspectable files, not only in a session transcript.
3. **Access is not authority.** Discovering a folder, repository, credential, runtime, or account does not authorize use, mutation, disclosure, spending, or external effects.
4. **Evidence precedes inference.** Project and identity knowledge comes from recoverable sources or explicit user confirmation.
5. **Unknowns remain unknown.** Label assumptions, contradictions, stale claims, and open questions rather than filling templates with plausible fiction.
6. **Start with the smallest justified structure.** Add an organization, knowledge system, agent team, Rail, or living-knowledge process only when the durable concern requires it.
7. **One live work authority per coordinated project.** When work must survive sessions, roles, dependencies, review, or approval, the project binds one Rail ledger.
8. **Installed agents have no inherent authority.** Runtime permissions, budgets, tools, data access, review gates, and stopping rights must be explicitly bound.
9. **Discovery is progressive and revocable.** Machine metadata, path inventory, file metadata, content access, external transmission, and mutation are separate grants.
10. **Deterministic controls surround probabilistic interpretation.** Models may interpret, compare, question, and draft; deterministic code owns permission checks, schemas, writes, credentials, installation, rollback, and verification.
11. **The user can leave.** The resulting Markdown, manifests, repositories, and ledgers remain usable without Workframe Origin or a particular model provider.

## Long-term definition of success

A mature system may eventually let a non-specialist authorize relevant evidence, conduct a meaningful Socratic dialogue, persist a customized Architectonic system, organize existing projects without destroying their boundaries, attach Rails only where coordination requires them, bind agents to explicit permissions and runtimes, and open a Workframe workspace where a later session can continue without the user explaining the entire world again.

That is a destination, not a claim about the current branch.
