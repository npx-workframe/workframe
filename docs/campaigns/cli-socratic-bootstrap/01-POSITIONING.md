# Product Positioning

## 1. Name

# Workframe Origin

**Package and command:** `workframe` / `npx workframe`  
**Campaign qualifier:** Origin  
**Internal category:** Socratic bootstrap and persistent-context formation CLI

“Origin” identifies the first moment at which an otherwise generic agent becomes grounded in a particular human, purpose, body of evidence, authority structure, and working environment. It is a campaign and product-mode name, not a requirement to rename the existing Workframe package.

## 2. Tagline

# Your work should outlive the chat.

Supporting line:

> Turn the scattered evidence on your computer into a durable, user-owned operating context that any authorized agent can understand and continue.

## 3. One-sentence description

Workframe Origin is a consent-driven Socratic bootstrap CLI that discovers available agent runtimes and authorized local evidence, helps the user form a durable Architectonic account of purpose, identity, knowledge, authority, projects, and unknowns, and attaches that system to a persistent Workframe workspace.

## 4. One-paragraph description

Workframe Origin begins by safely inspecting the machine rather than assuming a blank environment: it identifies installed runtimes such as Claude Code, Codex, Hermes, Pi, or other supported agents; detects usable model access without exposing credentials; and asks the user exactly what may be used. It then progressively inventories authorized folders, files, repositories, and workspaces, using deterministic code for discovery and permissions and an authorized model only for semantic interpretation. Through an evidence-led Socratic dialogue ordered from teleology to ontology, epistemology, doctrine, authority, projects, and operations, it turns scattered material and explicit user decisions into a customized Architectonic system of record. Finally, it organizes or attaches the user's existing projects, creates Rails where durable coordination is justified, binds agents to explicit permissions and runtime adapters, and opens a Workframe workspace where future sessions can resume from the same user-owned context.

## Product promise

A user should not have to spend the first hour of every AI session reconstructing the same world.

The product promise is not that a vendor’s model will secretly remember the user. The promise is that the user will own a clear, portable, source-grounded account of:

- what they are trying to achieve;
- what entities and projects exist;
- what is known, assumed, contradicted, stale, or unknown;
- which documents and repositories support those claims;
- who may decide, approve, delegate, stop, publish, spend, or mutate;
- which agents, skills, tools, models, and runtimes are available;
- what work is active and where its canonical Rail lives;
- which private areas remain outside AI access;
- what the next authorized agent should read and do.

## Audience spectrum

The same underlying system must serve radically different users without requiring them to understand its ontology.

### The accessibility-first novice

A 94-year-old person using a heavily zoomed Windows interface should receive one plain-language question at a time, large and legible output, explicit back and stop controls, and no terminal or ontology jargon. The system should never interpret confusion as consent.

### The skeptical professional

A psychiatrist or other regulated professional who recently began experimenting with AI should first be helped to define prohibitions, confidentiality boundaries, local-only zones, and the separation between personal, professional, public, and protected information. Skepticism should become explicit doctrine and privacy policy rather than friction the installer tries to bypass.

### The capable but non-current technologist

A person comfortable with software but not current on agent runtimes, skills, context systems, or local model tooling should be able to accept a recommended setup while inspecting the reasoning and consequences behind it.

### The old-school programmer

A programmer whose computer is a carefully evolved personal system should receive exact commands, paths, discovery methods, proposed writes, mount modes, data flows, and rollback behavior. The system should treat the machine as the user's territory, not as an empty deployment target.

### The agentic power user

An experienced operator should be able to select runtimes, providers, profiles, repositories, mounting modes, Architectonic layers, agent packs, permissions, and deployment targets directly, while still benefiting from contradiction detection and document-guided formation.

## Positioning against adjacent categories

### Not an AI memory feature

Hidden model or platform memory is provider-bound, difficult to inspect, uncertain in provenance, and often unable to distinguish fact from inference. Workframe Origin persists explicit user-owned files and manifests.

### Not a disk indexer

The purpose is not to catalog everything. Discovery exists to identify relevant evidence and boundaries for a human–AI operating context. The correct result may exclude most of the machine.

### Not a static questionnaire

Questions are selected from actual gaps, contradictions, and consequences found in authorized sources. The system should not ask for information already recoverable from evidence.

### Not a universal folder template

Architectonic layers are added only when the concern needs a durable home. A single project may remain a project. An organization, constitution, knowledge system, agent team, graph, loop, or living-knowledge process must be justified.

### Not a replacement runtime

Claude, Codex, Hermes, Pi, and future agent runtimes remain replaceable execution engines. Workframe Origin discovers, authorizes, and binds them; it does not need to reinvent their reasoning loops.

### Not surveillance

The system asks permission progressively and records grants. It may inspect only approved scopes, may transmit only separately approved material, and must support exclusion, revocation, and deletion.

## Core vocabulary

| Term | Meaning |
|---|---|
| **Formation** | The process of turning evidence and explicit decisions into durable purpose, ontology, knowledge, authority, and operational contracts. |
| **Evidence inventory** | A local, permission-bounded index of candidate folders, files, repositories, and source metadata. |
| **Source attachment** | A mounted, referenced, copied, imported, or cloned source linked to a project or knowledge domain with provenance. |
| **Doctrine** | Inspectable purpose, principles, judgment rules, evidence policy, incentives, and method. |
| **Architectonic instance** | The customized file-native system of purpose, governance, actors, projects, knowledge, skills, agents, Rails, and upkeep created for the user. |
| **Workframe workspace** | The execution and collaboration surface that presents chat, files, agents, rooms, runs, approvals, and artifacts. |
| **Runtime adapter** | A bounded interface to an existing agentic runtime or inference provider. |
| **Formation session** | A resumable setup process with grants, evidence references, questions, decisions, proposed writes, checkpoints, and verification state. |
| **Rail** | A project's single canonical live-work ledger when coordination must survive sessions, roles, dependencies, review, or approval. |

## Canonical message

> You already have a life, work, files, projects, decisions, and tools. Workframe Origin does not ask you to start over inside a chat. It helps you decide what matters, safely examines what you authorize, questions contradictions, records what is known and unknown, and builds a durable workspace that future agents can understand.
