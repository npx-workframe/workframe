## Recovered paper thesis

When language becomes operational, it becomes constitutional material. A language-native human–AI organization therefore needs explicit structures for constitution, actors, ontology, memory, knowledge, technē, judgment, action and production, social coordination, higher-order wisdom, and environmental reality. The recovered formal model is `S = <C,A,O,M,K,T,J,R,P,G,E>`; this campaign does not assign undocumented meanings to symbols whose exact definitions were not recoverable from the canonical paper.

## Alignment

| Constitutional concern | Minimal bootstrap behavior |
|---|---|
| Telos before mechanism and ontology | `start` first asks what the user wants to accomplish, for whom, and what success means. Organization, business, project, or none yet is asked only afterward as a provisional form. |
| Constitution before consequence | The first slice is plan-only. It cannot inspect paths, call providers, or mutate files. |
| Actors and authority | A detected runtime is only a candidate. Use requires explicit authorization. Access never implies authority. |
| Ontology from evidence | No entity, project, role, or relation is created from filenames alone. Later claims require source evidence or explicit confirmation. |
| Memory is not truth | Chat and model memory remain hints. Durable accepted claims must be written to inspectable files with provenance. |
| Knowledge preserves uncertainty | Facts, decisions, assumptions, contradictions, and known unknowns remain distinct. |
| Judgment may be probabilistic | An LLM may rank questions or draft doctrine after authorization. It may not approve its own access or writes. |
| Consequence is deterministic | Permissions, schemas, file writes, installation, rollback, and verification remain deterministic. |
| Polis/agora is downstream | Multi-user rooms, teams, markets, and social surfaces are not part of the bootstrap MVP. |
| Sophia is not simulated | The system does not claim wisdom. It exposes evidence, uncertainty, authority, and consequences for human judgment. |
| Physis constrains the system | The actual machine, files, runtimes, provider state, legal boundaries, and external world outrank generated narratives. |

## Constitutional invariants for this branch

1. The system asks **to what end, for whom, and toward what success condition** before proposing an entity type or installation.
2. Discovery is read-only and progressively authorized.
3. Detected runtimes and credentials are candidates, not grants.
4. No file content leaves the machine without a separate explicit grant.
5. No durable claim is accepted solely because a model generated it.
6. No mutation occurs before the user sees the proposed consequence.
7. Architectonic remains the durable organizational protocol; this CLI does not reimplement its layers.
8. Workframe remains the execution surface; this CLI does not create a second workspace engine.
9. Existing repositories remain authoritative in place unless the user explicitly chooses clone, copy, or move.
10. The user can stop with a useful plan and no installation.

## Paper-level correction to the original campaign

The original campaign described the entire eventual system at once. That obscured the constitutional dependency order. The corrected build sequence is:

```text
teleological intent and success condition
  -> provisional carrier form, if one is justified
  -> explicit authority to inspect
  -> evidence inventory
  -> ontology and epistemic classification
  -> proposed doctrine and constitution
  -> explicit authority to write
  -> Architectonic instantiation
  -> Workframe attachment
  -> runtime execution
```

Only the first two lines are represented in the initial plan-only slice, using existing runtime discovery as environmental input. Later stages must earn their existence through a verified preceding slice.
